# 試着の間 ― 触れる作品空間

スマホで「作品そのものに触れる」ための、インタラクティブな作品空間サイト。
手・ネイル・身体性・痕跡・粒子・半透明・発光を、静かで上品な操作感に落とし込んでいます。

---

## まず開く

**`このサイトを開く.command` をダブルクリック**（または `index.html` をダブルクリック）

### スマホで見るとき

**公開URLで見るのがいちばん確実です** → https://ebiko5555.github.io/shichaku-no-ma/

`index.html` の1枚だけをAirDropで送っても動きますが、その場合**動画（「間」の場面）だけは映りません**。
画像は全部ファイルの中に埋め込んでありますが、動画は容量が大きすぎるため
`assets/watercolor-hands.mp4` として外に置いてあります。
動画も含めて手元で見たい場合は、`index.html` と `assets` フォルダをセットで送ってください。

## ファイル構成

```
触れる作品空間_没入版/
├── index.html                   ← 完成サイト（1枚で完結。これを開く／スマホに送る）
├── 文章.txt                      ← ★サイトに出る文章はここを直す
├── ひな型.html                   ← デザインや配置を直すのはこちら（普段は触らない）
├── assets/                      ← 元画像。差し替えはここに入れる
│   ├── hand-orb-01.png             手が光球を持つ（中心作品）
│   ├── reference-space-hand.png    宇宙ハンド（球体へ手をのばす）
│   ├── reference-thinking-hand.png 思唯手（エッチング風）
│   ├── reference-nail-orb.png      発光するネイル
│   ├── real-nails.jpg              実写の爪（「還」の場面）
│   ├── watercolor-hands.mp4        水彩風ピンクの手（「間」の場面）
│   └── hand-trace.png              予備（現在は未使用）
├── 画像を反映して書き出す.command   ← ひな型＋画像 → index.html を作り直す
├── build.py                     ← 上のコマンドの中身
├── このサイトを開く.command
└── 旧版_CSS版.html.bak           ← 最初に作ったCSSだけの版（保険）
```

外部ライブラリは一切使っていません。すべて手書きのコードです。

## 7つの場面（構成）

映画のように、場面を絞って組んでいます。縦に情報を並べるポートフォリオにはしていません。

| | 場面 | 何が起きるか |
|---|---|---|
| 序 | PROLOGUE | 暗闇から手が静かに立ちあがり、タイトルが一字ずつ現れる |
| 触 | TOUCH | **画面のどこでも触れると、膜がふるえて波が走り、粒子が飛ぶ** |
| 変 | TRANSFIGURE | スクロールで作品が変質。**表面が粒子に分解し**、別の作品へ渡っていく |
| 間 | WATERCOLOUR | 水彩のピンクから、ふたつの手が湧きあがる映像。ひと呼吸おく場面 |
| 試 | TRY ON | **艶・磨・にじ・AURA の4アトリエ**へ。実際にネイルを試着する |
| 読 | WORKS | 作品が背後へ退き、タイトル・解説・研究の文脈が読めるようになる |
| 残 | TRACE | これまでの作品の一覧 |
| 還 | REAL | **実写の爪の写真**が現れ、「ととのえる」（実際の施術の記録）へ還る |

### 外に繋がっている先

| 場面 | 行き先 |
|---|---|
| 試 | [艶](https://ebiko5555.github.io/tsuya-atelier/) / [磨](https://ebiko5555.github.io/migaki-atelier/) / [にじ](https://ebiko5555.github.io/niji-atelier/) / [AURA](https://ebiko5555.github.io/aura-atelier/) |
| 還 | [ととのえる ― 爪と手のケア](https://ebiko5555.github.io/nail-care-showcase/) |

「ととのえる」側にも**試着の間へ戻る道**を付けたので、行き止まりになりません。

### 場面の並びの考え方

光でできた手（序・触・変）→ ひと呼吸（間）→ 自分で試す（試）→ 読んで理解する（読・残）
→ **画面を出て、実際にふれられる爪へ還る（還）**

研究ノートに書いた「視覚から、リアルに触れることへの回帰を」を、
そのまま画面の流れにしてあります。最後が実写で終わるのが要点です。

### 操作
- **タップ / 長押し / なぞる** … 触れた場所から膜がふるえ、光と粒子が広がる
- **スクロール** … 作品が変質していく（手 → 粒子 → 輪郭）
- **スマホを傾ける** … 空間がゆっくり追従する

## 技術的な話（かみくだいて）

### なぜ「1枚のファイル」なのか
触れたときの波紋は **WebGLのシェーダー**（画面の点ひとつひとつを計算で塗る仕組み）で描いています。
これを使うと、普通のCSSでは出せない「膜がふるえる」表現が、スマホでもなめらかに動きます。

ただしブラウザの安全機能で、**パソコンの中の画像ファイルを直接この仕組みに渡すことができません**。
そこで `build.py` が画像を縮小してファイルの中に埋め込んでいます。おかげで、
ダブルクリックでも、スマホに送っても、ネットがなくても、ちゃんと動きます。

### スマホで重くならない工夫
- 解像度の上限を機種に応じて下げている（スマホ1.3倍・PC1.75倍）
- 画像は長辺1200pxまで縮小して埋め込み（全部で約0.9MB）
- 派手な処理は「触」と「変」の場面だけ。読む場面は軽くしてある
- 別のタブを見ているあいだは描画を止める
- WebGLが動かない環境では、自動的にCSSだけの静かな背景に切り替わる

## 自分の作品に差し替える方法

### 画像を変える（いちばん簡単）
1. `assets/` の中の画像を、**同じファイル名のまま**自分の画像に置き換える
   （例：`assets/hand-orb-01.png` を消して、自分の作品を `hand-orb-01.png` という名前で保存）
2. **`画像を反映して書き出す.command` をダブルクリック**
3. `index.html` が新しい画像で作り直される

> **コツ**：背景が黒に近い画像がいちばん綺麗に空間へ溶けます。
> 明るい背景の画像でも使えますが、「思唯手」のように白黒反転して光る線として表示されます。

### 文章を変える
1. **`文章.txt`** を開く（VS Code か、メモ系アプリ。テキストエディットでも安全です）
2. `[見出し]` の**下の行**を書き換える。`[ ]` の行そのものは変えない
3. **`画像を反映して書き出す.command` をダブルクリック**

```
[作品1の名前]
宇宙ハンド              ← ここだけ書き換える

[作品1の解説]
暗闇のなかで、手がひとつの球体へ手をのばす。…
```

- 改行したいところで Enter を押せば、サイトでも改行されます
- 長い文章は改行せず1行で書けば、画面幅に合わせて自然に折り返します
- 行のあたまが `#` の行は説明なので、消しても残してもかまいません
- HTMLのタグを書く必要はありません（`<` や `>` を書いても、そのまま文字として表示されます）

> 書き出したとき、項目名を間違えていると
> 「※ 文章.txt に見あたらなかった項目」と画面に出るので、そこを直してください。

### 色を変える
`ひな型.html` の上のほうにある `:root{ }` にまとまっています（`--blue` `--gold` など）。

### 画像の大きさ・画質を変える
`build.py` の上のほうにある `MAX_PX`（大きさ）と `QUALITY`（画質）の数字を変えます。
大きくすると綺麗になりますが、ファイルが重くなります。

## 調べた上での設計判断（なぜこの形にしたか）

実装前に、いま評価されているインタラクティブ作品サイトの作り方を調べ、次の点を取り入れました。

- **「ページ」ではなく「場面」で構成する** … 要素を並べるのではなく、映画のように5場面に絞り、
  静かな間（ま）と見せ場を作る
- **文字そのものを動かす** … 3Dを足すより、文字が一字ずつ立ちあがるほうが、
  軽いのに没入感が出る（キネティック・タイポグラフィ）
- **効果は要所だけに集中させる** … 全部の場面を見せ場にすると、かえって何も印象に残らない。
  読む場面はあえて静かにしてある
- **触覚はシェーダーで描く** … レイアウト計算を通さないので、スマホでもなめらかに反応する
